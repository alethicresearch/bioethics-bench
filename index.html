Research architecture

Resource → Task → Evaluation

Bioethics Bench is designed so that the normative object does not become synonymous with the first computational method used to study it.

01

Resource

Decision question, scenario, stipulated facts, candidate policies, provenance and warrant, controlled representations, geometry, version lineage, review state, and rights.

02

Task

An explicit contract specifies what a system does with the resource. The first mature reference task is sacre-qccs-v1; it is a projection, not the resource ontology.

03

Evaluation

Model, human evaluator, repetitions, perturbations, retry rules, metrics, latency, cost, and other experimental conditions are recorded separately from both resource and task identity.

Reference-task reproducibility

A complete 68-record projection test

The existing SACRE/QCCS use of the corpus was formalized as an explicit sacre-qccs-v1 task contract and tested through a read-only adapter across the entire current Full Corpus.

execution- or task-semantic differences found across current record projections

36 / 68

stale provenance-bearing content hashes detected in SACRE's older vendor state

What that result means

The detected drift was provenance-only. After re-pinning, the adapter projection and SACRE vendor payload were byte-for-byte identical and regression tests passed. No model/QCCS rerun was required because executable semantics had not changed. This is a reproducibility and identity result—not evidence that QCCS is reliable, construct-valid, or morally correct.

Source grounding

Provenance is part of the measurement problem

A candidate can be structurally valid while misrepresenting what a source supports. Bioethics Bench therefore distinguishes direct policy evidence, disclosed source-informed policy inference, and framework-derived policy, while current ontology work models the many-to-many relation between sources and represented policies more explicitly.

Direct policy evidence

The source itself supports a sufficiently close policy recommendation for the represented decision.

Source-informed inference

The source supports an orientation, preference, principle, or premise; the Bench separately discloses how that material becomes an executable policy.

Framework derivation

The executable policy is a Bench-authored operational derivation from a named normative framework or principle set, not a quotation from the source.

Inspect, cite, and reuse

Make the exact research object reconstructable

For record-level reuse, identify the record_id, version, and content_hash. For computational results, additionally identify the exact resource snapshot, task specification, and evaluation/execution condition.
