# Featured v1 — Scenario and Policy-Representation Calibration Audit

**Date:** 2026-08-30  
**Status:** active calibration audit; released records remain unchanged  
**Scope:** 20 current Featured v1 cases  
**Governing standard:** `docs/CANDIDATE_POLICY_SPACE_AUDIT.md`

## Purpose

This audit is the first calibration stage for the corrected Bioethics Bench construction standard. It asks whether each released case represents a sufficiently specified **Scenario** and a defensible, source-grounded field of **Policy candidates** from the Public / affected-community, Expert / professional, and Ethical Framework source domains.

It does **not** treat `decision_question` as a formal SACRE input or require the candidate field to exhaust branches named in that question. A practical question is reader-facing metadata. The substantive audit asks whether the source-to-Policy construction preserved the natural substantively distinct positions supported by the evidence.

This pass is intentionally conservative about released material. It does not rewrite any v1 record. It identifies which cases appear strong as represented, which are valid but naturally low in demonstration richness, and which require the underlying sources to be reopened before a new explicit record version is considered.

## Audit labels

### Scenario

- **PASS** — Scenario is sufficiently specified for the represented Policy field.
- **REVIEW** — a factual, temporal, jurisdictional, or stipulation choice may be shaping the Policy field in a way that needs re-examination.

### Policy representation

- **PASS** — current record shows materially distinguishable, source-grounded positions within the relevant source domains; cross-source convergence is allowed and often desirable.
- **REVIEW** — possible near-duplication, position merging, source-to-policy overtranslation, omitted serious position, or source-class geometry imposed by construction.
- **RECONSTRUCT** — a likely substantive mismatch exists between the Scenario and at least one represented Policy candidate or source position.

### Demonstration richness

- **HIGH** — naturally supported field exposes several informative normative relations and is a strong SACRE / RE-Iteration demonstration candidate.
- **MEDIUM** — useful SACRE object, but much of the field organizes around one or two principal poles or threshold differences.
- **LOW** — valid research object whose serious sources substantially converge; retain as scholarship/executable material if otherwise sound, but do not force disagreement for display value.

These are calibration judgments, not model-derived scores.

## Cross-case findings

### 1. The main problem is not universally “too little diversity”

Several Featured cases are already strong SACRE objects: F02, F05, F07, F08, F10, F11, F12, F14, F15, F16, and F19 are especially promising at the record level.

Other cases are less dramatic because serious sources substantially converge. F06 and F18 are the clearest examples. Their lower demonstration richness should be recorded rather than repaired by manufacturing disagreement.

### 2. The most important construction risk is source-to-Policy translation

The audit repeatedly encounters candidates described in provenance as **Bench editorial translations** of broader attitudes, concerns, or guidance. Translation is unavoidable in a Policy-candidate resource, but it creates the central scholarly burden: the resulting Policy must be warranted strongly enough by the source that a different editor would recognize the inference.

The final all-200 audit therefore needs to examine not merely whether a citation exists, but whether the source supports the *specific represented policy implication*.

### 3. Fixed `2 × 2 × 2` geometry should not govern construction

F03 and possibly F20 illustrate why. If the source evidence naturally supports one defensible Public position rather than two, the resource should preserve that geometry. The study protocol can later select naturally symmetric cases where symmetry is experimentally useful.

### 4. Temporal and hypothetical consistency is a separate Scenario gate

F09 exposes a problem that ordinary candidate-distinctness review can miss: every candidate must address the **same represented Scenario**. A current institutional prohibition is not automatically a Policy position about a stipulated future state in which the factual preconditions have changed.

### 5. Framework completeness requires active normative scholarship search

Framework construction must not simply derive two convenient contrasting positions from a familiar small canon. F17 raises the possibility that a serious normative family — animal-rights / categorical anti-use reasoning — may have been omitted. The all-200 pass should explicitly ask which major normative position families are live for the Scenario before selecting framework candidates.

### 6. Benchmark stipulations can improve comparability and still distort the normative object

F16 and F19 are useful cases partly because quantitative stipulations make the trade-offs concrete. Those stipulations are transparent, which is good. They should nevertheless be audited for **normative leverage**: whether the chosen value was merely needed to make the Scenario determinate or was selected because it creates a desired balance or interesting result.

## Priority source re-open queue

The first deeper research pass should proceed in this order:

1. **F09 — Heritable genome editing:** resolve temporal / hypothetical mismatch.
2. **F03 — Periviable resuscitation:** recover natural Public and Expert Policy geometry without using the decision-question branches as a target.
3. **F17 — Animal research:** test framework completeness, especially serious rights-based positions.
4. **F04 — Brain death accommodation:** test whether Expert candidates are substantively separate policies or nested procedural formulations.
5. **F20 — Neural organoids:** test whether public evidence warrants two specific Policy constructions.
6. **F18 — Antimicrobials:** test whether low diversity is genuine cross-source convergence.
7. **F01 / F13:** lighter checks for possible source-to-policy overtranslation.
8. **F16 / F19:** stipulation-leverage audit.

The remaining cases should still receive ordinary whole-source release review, but they do not currently show an obvious representational defect from the released records alone.

## What happens after Featured calibration

This audit is **not** the final corpus audit.

Once the priority source re-opens above stabilize the rubric, apply the same Scenario / Policy-representation audit to **all 200 planned Bench cases before final resource freeze**. Existing developmental records may be reopened even if they already pass schema validation, citation resolution, or prior executable checks.

The all-200 pass must record at least:

- Scenario adequacy;
- source-to-Policy fidelity;
- natural candidate count by source domain;
- within-pool distinctness;
- cross-source independence;
- position merging / omission risks;
- concise/detailed invariance;
- stipulation leverage;
- SACRE suitability;
- demonstration richness;
- final action: retain / revise-new-version / hold / research-complete-not-executable.

## Release rule

Featured v1 is already public. This audit therefore changes **classification and future construction rules**, not historical bytes. Where deeper review confirms a material defect, create an explicit new record version with a documented diff, updated provenance, regenerated hashes, and a fresh release review. Do not overwrite the released v1 object.
